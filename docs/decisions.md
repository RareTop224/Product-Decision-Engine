# Decisions

## D-001 — Python standard library for the first slice

Первое ядро использует Python 3.11 и стандартный `unittest`. Это делает расчёты
воспроизводимыми без установки инфраструктуры и не мешает позднее подключить
FastAPI/PostgreSQL после решения по Phase 0.

## D-002 — JSON Golden Dataset

Исходные данные Phase 0 хранятся в нескольких читаемых JSON-файлах. Business
logic не зависит от формата: loader отделён от доменных расчётов. Это позволяет
перенести сущности в PostgreSQL без переписывания TCO calculator.

## D-003 — Integer RUB amounts

Тестовые цены хранятся целыми рублями. Float для денег не используется. Если
источники потребуют копейки, модель будет мигрирована на integer kopecks без
изменения алгоритма.

## D-004 — Explicit consumable channels

У продукта явно перечислены обязательные каналы расходников, например `black`
или `cyan`. Каждая связь с расходником также задаёт применимость к страницам:
`mono_pages`, `color_pages` или `all_pages`. Движок не угадывает расход чернил
по типу печати и обнаруживает отсутствующий канал как неполные критичные данные.

## D-005 — One canonical OEM replacement per channel in Phase 0

Для каждого канала Golden Dataset выбирает один явно обоснованный OEM replacement
package. Оптимизация комбинаций standard/high-yield упаковок пока не реализуется:
она может скрыть ошибки данных и не нужна для проверки базовой гипотезы. Выбор
канонического расходника должен быть объяснён evidence/notes.

## D-006 — Explicit page-equivalent weights

Некоторые maintenance items имеют разный ресурс при монохромной и цветной
печати. Например, опубликованные 16 000 mono / 4 000 color pages означают, что
одна цветная страница расходует четыре эквивалентные единицы ресурса. Связь
product–consumable хранит явные `mono_page_weight` и `color_page_weight`; движок
не выводит их из технологии или названия расходника.

## D-007 — Maintenance completeness is explicit

Отсутствие maintenance link само по себе неоднозначно: отдельного элемента может
не быть, либо его просто не исследовали. Поэтому у продукта есть проверяемый
`maintenance_data_status`. Значение `incomplete` блокирует TCO, а
`not_published` сохраняется как предупреждение.

## D-008 — Conflicts remain visible

Наличие одного выбранного `verified` факта не удаляет противоречащий источник.
Конфликт сохраняется как отдельный `Evidence` со статусом `conflict` и попадает
в аудит полноты. Это позволяет считать по более приоритетному источнику, не
создавая ложного впечатления, что исходные данные однозначны.

## D-009 — Промежуточная рекомендация не равна Phase 0 gate

До достижения 30 моделей отчёт может выдать процессную рекомендацию
`CONTINUE PHASE 0`, только если все заданные сценарии имеют хотя бы две
рассчитываемые альтернативы, есть хотя бы одна смена победителя относительно
цены покупки и контроль чувствительности даёт не менее двух разных победителей.
Это означает лишь наличие раннего сигнала для продолжения сбора данных.
Итоговый `GO`, `REASSESS` или `NO-GO` по этой рекомендации не выставляется.
